# Minecraft AI Admin Bot — версия для Render (бесплатный план)

Telegram-бот-администратор Minecraft-сервера (управляет файлами по SFTP,
использует Groq для понимания команд на естественном языке). Это порт
оригинального проекта Replit «Minecraft AI Admin Bot» под хостинг Render.

## Новое: установка аддонов по ссылке

Telegram Bot API не позволяет боту скачать файл крупнее 20 МБ, даже на
платных инстансах — это ограничение самого Telegram, не Render. Поэтому
кроме отправки файла, бот принимает **прямую ссылку на скачивание**
архива: скачивает его сам через HTTP(S), в обход лимита Telegram.

- Просто пришлите ссылку в чат — если бот распознает в сообщении URL, он
  попробует скачать по нему архив.
- Ссылки на Google Drive («Поделиться» → «Копировать ссылку») обрабатываются
  отдельно — бот сам проходит через страницу подтверждения для больших
  файлов.
- Для любого другого сайта/облака нужна ссылка, которая отдаёт сразу файл
  (или редиректит на файл) — если по ссылке возвращается HTML-страница
  вместо архива, бот сообщит об этом.
- Максимальный размер скачивания ограничен переменной
  `ADDON_MAX_DOWNLOAD_MB` (по умолчанию 300 МБ) — увеличьте её при
  необходимости, но учитывайте лимит RAM бесплатного инстанса Render
  (512 МБ).

## Важные отличия от Replit

**Background Worker недоступен на бесплатном плане Render** — бесплатно
можно развернуть только **Web Service**. Но сам бот работает через
**long polling** Telegram и в принципе не принимает HTTP-запросы.

Чтобы Render признал сервис "живым" на бесплатном плане, в `main.py`
добавлен минимальный HTTP-сервер: он слушает `$PORT` и отвечает "ok" на
любой запрос, а сам Telegram-polling крутится в отдельном потоке рядом с
ним. Никакой дополнительной настройки не требуется — это уже встроено в код.

### Ограничения бесплатного плана, о которых стоит знать

- **Сервис засыпает после 15 минут без входящих HTTP-запросов** и
  просыпается 30–60 секунд при следующем запросе. Пока сервис спит, он не
  опрашивает Telegram и не получает сообщения. Чтобы бот не засыпал,
  настройте внешний пинг каждые 5–10 минут на URL вашего сервиса (например,
  через [cron-job.org](https://cron-job.org) или UptimeRobot) — он будет
  бить в тот же health-check эндпоинт, который слушает бот.
- **Persistent Disk недоступен на бесплатном плане.** Файловая система
  эфемерна: `memory.json` (память последних задач) и `runtime_config.json`
  (переопределённые SFTP host/port) сбрасываются при каждом передеплое,
  рестарте или "просыпании" сервиса. Это не критично для работы бота — он
  продолжит выполнять команды, просто без долгой истории и без сохранённых
  вручную host/port между перезапусками (их можно будет один раз обновить в
  переменных окружения `SFTP_HOST`/`SFTP_PORT`).
- 750 бесплатных часов инстанса в месяц на весь workspace — для одного
  бота этого обычно достаточно, но учитывайте, если запускаете несколько
  бесплатных сервисов одновременно.

Если захотите убрать эти ограничения (постоянно активный сервис, отсутствие
холодного старта, персистентный диск для памяти) — это план Starter,
от $7/мес.

## Деплой на Render

### Вариант 1 — через render.yaml (Blueprint)

1. Залейте эту папку в свой GitHub/GitLab репозиторий.
2. В Render: **New → Blueprint**, укажите репозиторий — Render подхватит
   `render.yaml` и создаст Web Service на бесплатном плане автоматически.
3. Заполните переменные окружения без значений (см. ниже) в Dashboard →
   Environment — они помечены `sync: false`, то есть Render попросит ввести
   их вручную и не будет хранить в репозитории.

### Вариант 2 — вручную

1. **New → Web Service**, подключите репозиторий.
2. Runtime: **Python 3**. Instance Type: **Free**.
3. Build Command: `pip install -r requirements.txt`
4. Start Command: `python main.py`
5. Добавьте переменные окружения (раздел ниже). Render также сам
   прокидывает переменную `PORT` — её задавать вручную не нужно, код её
   уже читает.

## Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | Токен бота от @BotFather |
| `TELEGRAM_ALLOWED_USER_ID` | да | Telegram user ID владельца (единственный, кто может им пользоваться) |
| `SFTP_HOST` | да* | Адрес SFTP Minecraft-сервера |
| `SFTP_USER` | да | Логин SFTP |
| `SFTP_PORT` | нет | По умолчанию 22 |
| `SSH_PRIVATE_KEY` | да | Приватный SSH-ключ (RSA/Ed25519/ECDSA), многострочный или с `\n` |
| `GROQ_API_KEY` | да | Ключ Groq API |
| `GROQ_MODEL` | нет | По умолчанию `llama-3.3-70b-versatile` |
| `ADDON_MAX_DOWNLOAD_MB` | нет | Лимит размера скачивания по ссылке в МБ, по умолчанию 300 |

\* `SFTP_HOST`/`SFTP_PORT` можно также менять на лету из самого бота
(кнопка «Изменить SFTP Host / Port»), но на бесплатном плане это изменение
не переживёт передеплой/пересыпание сервиса (нет персистентного диска).

Полный список переменных, которые нужно вручную задать в Dashboard, есть в
`.env.example`.

## Локальный запуск

```bash
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN=...
# ...остальные переменные из .env.example
python main.py
```

## Структура проекта

```
main.py                          # точка входа
minecraft_ai_admin/
  main.py                        # вся логика бота
  memory.json                    # память последних задач (создаётся заново)
  runtime_config.json            # переопределение SFTP host/port (создаётся заново)
requirements.txt                 # зависимости pip
render.yaml                      # Blueprint для Render (Web Service, free plan)
Procfile                         # альтернативная команда запуска
.env.example                     # список нужных переменных окружения
```

## Что изменилось по сравнению с версией Replit

- Убраны Replit-специфичные файлы: `.replit`, `.replitignore`, workflow-конфиг,
  `pnpm`/Node-часть workspace (бот целиком на Python, Node не требовался для
  его выполнения).
- Секреты теперь задаются как обычные переменные окружения Render, а не
  Replit Secrets — код их читает так же (`os.environ`), менять ничего не
  пришлось.
- Добавлен встроенный HTTP health-check сервер (слушает `$PORT`), чтобы бот
  можно было развернуть как бесплатный Web Service — Background Worker на
  бесплатном плане Render недоступен.
- Добавлены `render.yaml`, `Procfile`, `.env.example`, `.gitignore` для Render.
- На Replit файловая система была постоянной, поэтому `memory.json`
  сохранялся между запусками. На бесплатном Render персистентного диска нет,
  так что эта память сбрасывается при пересыпании/передеплое — при апгрейде
  до платного плана можно вернуть постоянство, добавив Persistent Disk и
  переменную `STATE_DIR`, указывающую на точку монтирования.
